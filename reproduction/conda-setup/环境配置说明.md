## 4. 安装方式与版本固定

### 4.1 为什么没有重新编译全部 vLLM CUDA 内核

安装前磁盘约剩 56 GB。为避免全量编译缓存占满共享磁盘，本次使用作者 setup.py 已支持的 `VLLM_USE_PRECOMPILED` 路径：

1. 验证 PyPI vLLM 0.10.2 源码包与作者代码中 229 个内核、构建及自定义算子接口相关文件的 SHA-256 一致。
2. 单独记录发布包中的生成文件/捆绑 FlashAttention 文件，不把它们误报为作者改动。
3. 下载固定的官方 vLLM 0.10.2 wheel，并验证完整 SHA-256。
4. 在独立源码副本中复用该 wheel 的原生扩展；Python 调度代码仍来自作者的提交。
5. 显式指定 wheel 路径，禁止 setup.py 自动退回 nightly。

该安装带本地版本标签 `0.10.2+continuum.316a587.precompiled`，用于区分作者 fork 与普通 PyPI 发行包。这不是声称作者原始环境使用了这个本地版本字符串。

目前不提供 CUDA 12.8 的 `nvcc` 编译器。若后续改动 C++/CUDA 源码，需要再安装匹配 Toolkit 并重新编译；不能直接用系统 CUDA 13.0 混编当前 PyTorch 2.8.0/cu128 环境。

### 4.2 保存的可复现材料

- `constraints.txt`：关键依赖版本约束。
- `requirements-runtime.txt`：初始基础包清单。
- `pip-freeze.txt`：最终实际安装版本，含 editable 源码路径。
- `conda-explicit.txt`：Conda 层的精确包清单。
- `environment.yml`：当前环境状态导出，不是可直接一键重建的文件；其中的自定义 vLLM 版本没有发布到 PyPI。
- `requirements-pypi-locked.txt`：不依赖本地 wheel 文件路径的 PyPI 运行依赖锁定清单；先安装原版 vLLM 0.10.2，再运行 `install_fork.sh` 安装作者源码及内置 agent。
- `large-wheel-manifest.json`：大包来源、尺寸和 SHA-256。
- `kernel-source-comparison.json`：原生代码兼容性核对。
- `environment-verification.json`：实际验证结果。
- `setup-summary.json`：完成状态、关键来源和命令行检查摘要。

`pip-freeze.txt` 保留原始安装来源，部分记录会指向本机 wheel；重建时应使用 Conda 明确包清单、上述 PyPI 锁定清单和固定作者源码三部分，而不是直接安装导出的自定义版本号。

Conda 环境变量设置 `PYTHONNOUSERSITE=1`，减少用户级 Python 包干扰；`PIP_CONSTRAINT` 指向本项目约束文件。后续不要随意运行 `pip install -U vllm torch transformers`。使用 uv 时也应显式传入约束文件。

### 4.3 安装过程中的兼容处理

Miniforge 的硬件自动探测试图读取无权限的系统 CUDA 版本文件时失败。没有修改文件权限或读取受保护内容；仅在安装/导出 Conda 命令中设置 `CONDA_OVERRIDE_CUDA=12.8`，使用已核对驱动可支持的版本作为解算提示。这个变量不安装 CUDA、不改变真实驱动，也不证明 GPU 推理成功。

大依赖由 PyPI 官方文件源下载并校验 SHA-256，再本地安装，以避免下载器在本机网络上的低速问题。没有使用未经校验的镜像替换包。

## 5. 验证范围

本次验证只使用 CPU，所有检查进程均隐藏 GPU。检查包含：

- 实际 Python 路径、核心依赖版本及 `pip check`。
- CPU 张量操作、vLLM import 和原生扩展加载。
- `continuum` 调度策略配置是否被作者代码接受。
- LMCache 原生扩展、mini-swe-agent、数据处理与绘图库导入。
- 命令行入口检查。

具体通过/失败以 `environment-verification.json` 及命令行日志为准。**环境加载验证不等于 GPU kernel 执行验证，更不等于论文性能复现。**
